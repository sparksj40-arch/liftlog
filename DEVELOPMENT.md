## Checkpoint 4 — recovery, private media transfer and transcription import

Continues checkpoint 3, with no production writes or account access. Explicit optional photo snapshot creation and restore in Settings uses the existing short-lived Drive `drive.file` grant. Each snapshot is a new standalone JSON file, not public or shared intentionally. App checks sole ownership and no additional sharing permissions before uploading and restoring, then reads back and verifies content; refuses mismatched image IDs without partially merging. Restores missing images only, not event metadata. A snapshot includes all local stored media (progress, food, Planner attachments, including retained/orphan images), maximum 20 MiB serialized; use complete local JSON backup for larger sets. It is not end-to-end encrypted. No automatic photo upload, background media sync, or deletion; later sharing by the owner is outside the app's control. Same authorized account and app OAuth client required on both devices. Actual Drive API permission behavior and restore on another device remain untested. If upload fails after creating an empty file, a nonusable empty snapshot may remain in Drive; it is not automatically deleted.

Planner supports converting pasted transcripts into editable notes/tasks with prose, bullets and explicit checked/unchecked markers. This is deterministic formatting, not AI OCR. Use Samsung keyboard recognition, OCR from another app, or ChatGPT manually; no image is transmitted for recognition. No native S Pen gesture implementation.

Settings now exposes extension revision conflict contents; no automatic conflict overwrite. Changing cloud database or creating a new Sheet resets extension remote confirmations and pending proposal cache; expired Google authorization is visible even when local changes are pending. These changes do not solve durable OAuth. All original V2 event schema, application URL and IndexedDB database name remain unchanged. See RELEASE-CHECKLIST.md for setup and acceptance gates.
